# График смен сотрудников

Тестовое задание на позицию Fullstack-разработчика: страница создания рабочего графика сотрудников по макету Figma.

- **Демо:** https://nazongit.alwaysdata.net
- **Код:** https://github.com/NazOnGit/russmarket-shifts
- **Стек:** PHP 8.4 · Laravel 13 · SQLite · Vue 3 (Composition API, `<script setup>`) · TypeScript · Pinia · Tailwind CSS 4 · Vite
- **Тесты:** 6 backend (PHPUnit) + 16 frontend (Vitest)

> Демо-смены заведены на неделю **9–15 ноября 2026**. Если открываете позже — нажмите ‹ или переключитесь на «Месяц».

---

## 1. Быстрый запуск

Нужны PHP 8.3+, Composer и Node.js 20+. База — SQLite (один файл), отдельный сервер БД не нужен.

```bash
git clone https://github.com/NazOnGit/russmarket-shifts.git
cd russmarket-shifts
composer setup   # зависимости, .env, ключ, миграции + демо-данные, сборка фронтенда
composer dev     # сервер Laravel + Vite → http://127.0.0.1:8000
```

Проверки:

```bash
php artisan test   # бэкенд: API, валидация, расчёт часов
npm test           # фронтенд: логика хранилища, даты, время, drag-and-drop
npm run typecheck  # проверка типов TypeScript
```

Сбросить демо-данные: `php artisan migrate:fresh --seed`.

## 2. Что реализовано

| Требование из задания | Как сделано |
|---|---|
| Календарь со списком сотрудников и сменами | Таблица «сотрудники × дни», часы сотрудника за период, цвет смены по шаблону |
| Поиск по ФИО | Фильтр строк в браузере, без учёта регистра и ё/е |
| Навигация по датам | ‹ › по неделе или месяцу, «Сегодня» |
| Переключение «Месяц / Неделя» | 7 колонок или все дни месяца; в месяце узкие ячейки с часами, колонка сотрудников закреплена |
| Быстрое назначение по клику на дату | Клик по дате в шапке выделяет столбец и открывает меню: Утро / День / Вечер / «Очистить день» |
| Назначение через ячейку + шаблон | Выделение кликом или протягиванием мыши, панель «Выделено: N ячеек · сотрудники · дни» → «Применить шаблон» или клик по карточке шаблона |
| Шаблоны «Утро», «День», «Вечер» | Назначаются любым сотрудникам, счётчик использования в периоде |
| Своя смена | Время ЧЧ:ММ (24 ч) с проверкой и подсказкой часов → «Поставить в выделенные»; смены через полночь поддерживаются |
| Редактирование | Назначение в занятую ячейку заменяет смену, «Очистить» удаляет |
| Покрытие смен | 0 — розовый, ≥ 1 — голубой; пересчитывается сразу, без перезагрузки |
| Drag-and-drop | Смену можно перетащить в другую ячейку (с Alt/Option — копия), шаблон — из панели на ячейку |
| Сохранение | «Сохранить» — в API с серверной валидацией; «Опубликовать» — сохранение + отметка периода; статус «Черновик / Опубликовано», предупреждение о несохранённых изменениях |

## 3. Как устроено

```
Браузер ── GET / ──▶ Laravel отдаёт одну HTML-страницу (resources/views/app.blade.php)
                         │  @vite → resources/js/app.ts
                         ▼
          Vue 3 + TypeScript: компоненты + хранилище Pinia (resources/js/stores/schedule.ts)
                         │  fetch('/api/...') — JSON (resources/js/api.ts)
                         ▼
          Laravel API: routes/api.php → FormRequest (валидация) → Controller → Eloquent → SQLite
```

- Все изменения на странице — черновик в браузере (Pinia). **Все способы назначения** (панель выделения, карточка шаблона, своя смена, меню даты, drag-and-drop) **вызывают одни и те же функции хранилища** (`assignToCells`, `applyTemplate`, `moveShift`), поэтому работают с общими данными.
- Покрытие, часы сотрудников и счётчики шаблонов — `computed`-значения: пересчитываются сами при любом изменении смен.
- «Сохранить» отправляет итоговое состояние видимого периода одним запросом; сервер заменяет смены периода в транзакции.

### Структура

| Путь | За что отвечает |
|---|---|
| `routes/api.php` | адреса API и какой метод контроллера их обрабатывает |
| `app/Http/Controllers/Api/ShiftController.php` | загрузка, сохранение (`sync`, транзакция) и публикация смен |
| `app/Http/Requests/SyncShiftsRequest.php` | валидация «Сохранить» |
| `app/Models/Shift.php` | модель смены, расчёт часов (в т. ч. через полночь) |
| `resources/js/stores/schedule.ts` | всё состояние страницы и действия: период, поиск, выделение, назначение, сохранение |
| `resources/js/api.ts` | единственное место, где фронтенд обращается к Laravel |
| `resources/js/components/schedule/` | таблица, панель выделения, меню даты, панель шаблонов, карточка смены |

### API

| Метод | Адрес | Назначение |
|---|---|---|
| GET | `/api/employees` | сотрудники |
| GET | `/api/shift-templates` | шаблоны смен |
| GET | `/api/shifts?from=YYYY-MM-DD&to=YYYY-MM-DD` | смены периода (до 62 дней) |
| PUT | `/api/shifts` | «Сохранить»: `{from, to, shifts[]}` — заменяет смены периода в транзакции |
| POST | `/api/shifts/publish` | «Опубликовать»: `{from, to}` — проставляет `published_at` |

Валидация: сотрудник и шаблон существуют, дата внутри периода, время `ЧЧ:ММ`, начало ≠ конец, не больше одной смены на ячейку (это же правило закреплено уникальным индексом `employee_id + date`). Ошибки возвращаются с кодом 422 и показываются в интерфейсе; черновик при этом не теряется.

## 4. Допущения

В макете не описано поведение некоторых элементов — принятые решения:

- В ячейке (сотрудник + дата) одна смена.
- Быстрое назначение по дате ставит шаблон всем видимым (с учётом поиска) сотрудникам в этот день.
- «Опубликовать» не отправляет данные во внешние системы: у смен периода заполняется `published_at` (в реальной системе — момент, когда график видят сотрудники). Новое сохранение снова делает период черновиком.
- Время шаблона копируется в смену; `shift_template_id` хранится для цвета и счётчика.
- Поиск фильтрует строки на клиенте; покрытие считается по всем сотрудникам, а не только по найденным.
- В макете у «Вечер 15:00–23:00» подписано «9 ч» — часы считаются из времени, получается 8 ч.
- Авторизации нет — в задании её не было. Вёрстка под десктоп; на узких экранах таблица прокручивается.

## 5. Что можно улучшить

- Сохранение сейчас заменяет все смены периода (просто и атомарно). Минус — у неизменённых смен меняется `id` и сбрасывается публикация. Улучшение: сравнивать по ключу «сотрудник + дата» и обновлять только изменённые.
- Защита от одновременного редактирования двумя пользователями (версия периода, проверка конфликта).
- Поиск на сервере с пагинацией, если сотрудников тысячи.
- Drag-and-drop с клавиатуры и на сенсорных экранах (сейчас — мышью, HTML5 DnD).
- E2E-тесты (Playwright) и CI со сборкой и деплоем.
